## По пунктам PO

1. **Скорость анимации без видимого состояния** → скорость стала **сегментированным radio** (`role=radiogroup`, `aria-checked`), активное деление залито акцентом. `GameAutoFsBar`.
2. **Краш при быстрых роллах** (`Must be called at the top of a setup function`) → `useBrutalToast()`/`useI18n` больше не зовётся в async-catch; `showError` вынесен в setup в `DiceGame`/`SlotGame`.
3. **Кнопки «едут» на мобиле** → бар переверстан: грид ставка/раунды, сегмент-скорость, чек «стоп при выигрыше», действия `Старт`/`Фуллскрин` с `flex:1 1 8rem`. Проверено 320/390 — без оверфлоу.
4. **Заголовок + режим над панелью** → новая `header`-секция над hero: название игры + тумблер FUN/LIVE + пояснение `// fun mode — без кошелька, виртуальные кредиты, та же RNG-математика` (i18n `games.common.modeExplain*`). Из нижней панели дубликат убран.
5. **Деплой `truebrutal.netlify.app` показывал ошибку вместо главной** → причина: env-плагин кидал **фатальный** экран, т.к. на Netlify не заданы `NUXT_PUBLIC_*`. Теперь при полностью пустом env — только warn (FUN-режим работает, LIVE скрыт); фатал только при **частичной** (битой) конфигурации. SPA-редирект в `netlify.toml` уже корректный.
6. **Перенос `ACCESS DENIED`** → `DancingText` группирует буквы по словам (`inline-block; nowrap`), перенос только по пробелу → «ACCESS» / «DENIED» целиком.
7. **Анализ готовности к тестовой сети** → [`ai/specs/testnet-readiness.md`](../ai/specs/testnet-readiness.md).

## Итог анализа

- **FUN** — готов на 100%, можно деплоить (после фикса env он и грузится).
- **LIVE/on-chain** — ~50%: программа написана полностью, но **не задеплоена**, IDL не сгенерирован, клиент `useCasinoProgram` — заглушки. Остаётся механическая проводка по плану ит.04. Из среды Claude недоступно (нет Rust/Solana/Phantom).

## Follow-up правки (2-й заход PO)

- **Тост наезжал на ✕** → у `BrutalToast` зарезервировано правое поле `pr-16`.
- **Непонятно когда стоп автороллов** → `useAutoPlay` возвращает `{played, wins, reason}`; по окончании раундов — тост с причиной: «без выигрыша за N раундов» или «N выигрышей»; ошибка (напр. недостаточно баланса) → её тост.
- **Нет перехода к игре при старте авто** → при старте `scrollIntoView('.bw-dice-hero-stage')` — монстр + кубик/барабаны сразу в кадре.
- **Бледные инпуты автороллов** → причина: `.bw-input` объявлен в scoped-стилях игр и не доставал до дочернего бара; стили инпутов добавлены в `GameAutoFsBar` (жирный `--bw-fg`).

## Follow-up правки (3-й заход PO)

- **🐛 Слот никогда не выигрывал** (0% пар/троек за 100k спинов). Причина: 3 барабана различались только последним байтом домена (`"slot"+reel`) — под FNV-1a это после `mod 6` давало **всегда разные** символы. Баг был и в on-chain `lib.rs`. Фикс: per-reel сдвиг nonce (`nonce + reel·0x9e3779b97f4a7c15`, домен `"slot"`) — синхронно в `lib.rs` и `shared/rng-verify.ts`. Теперь ~44% пар / ~2.8% троек (проверено Монте-Карло). **PO: для LIVE нужен передеплой программы** (FUN чинится сразу). Обновлены векторы теста и `rng.md`.
- **Кнопка «Крутить/Бросок» прыгала по высоте** → loading-слой `BrutalButton` теперь однострочный (`row`), высота не меняется между idle/спином.
- **Статус ∞ неясен** → заменён на чекбокс «∞ ON/OFF» с подсветкой; при включении инпут раундов гаснет.
